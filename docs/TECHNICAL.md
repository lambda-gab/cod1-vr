# Technical information

## How it works

The mod is a proxy `opengl32.dll` placed next to `CoDSP.exe`. It forwards every OpenGL call to the system's
`opengl32.dll` and hooks the game's renderer (a modified id Tech 3) to:

- turn the engine's dormant stereo path back on and render each world view once per eye, with each eye's
  asymmetric FOV and the runtime's IPD (single pass: the scene is set up once and drawn for both eyes);
- send the eyes to the headset through OpenXR (`XR_KHR_opengl_enable`), with the HUD and menus on a quad layer and
  the menu laser and grenade trajectory on an extra layer;
- move the view weapon and its muzzle flash to the tracked hand, write the aim into the game's view angles, add
  analog movement and roomscale to the usercmd, and map the controller buttons to game commands;
- show the controller buttons in the game's key hints (a detour in `cgamex86.dll`, reloaded with each level).

It only activates on `CoDSP.exe` 1.3 (the PE timestamp is checked) and stays inactive otherwise. It was built by
reverse engineering `CoDSP.exe` with [REA](https://github.com/morluto/rea) + Ghidra, using
[RTCWQuest](https://github.com/Team-Beef-Studios/RTCWQuest) as a reference. The full notes on addresses, hooks and
design decisions are in [`CoD_VR_RE.md`](CoD_VR_RE.md) (in Portuguese).

Without a headset, the mod shows both eyes side by side on the monitor.

## Optional data packs (manual install)

The installer generates them from your own copy of the game. To do it by hand:

```
python mods/build_pk3.py "<game folder>"
```

Then copy from `mods/out/` to `<game folder>\main`:

- `pakz_vr_nohands.pk3`: hides the first-person hands, so only the gun is in your hand. The launcher (VR tab > Player hands) makes and removes the same pack, which is what a manual install uses.
- `pakz_vr_text.pk3`: the two training texts that mention the mouse, rewritten for VR.

CoD 1.3 only loads packs whose name starts with `pak`. Delete a pack to undo it.

## Installer command line

`CoD-VR-Setup.exe /silent /dir="<game folder>" [/hands] [/shortcut]` or `/silent /dir="..." /uninstall`.

On updates `cod_vr.ini` is kept and the new defaults go to `cod_vr.ini.default`. Another `opengl32.dll` already in
the folder is backed up.

## Log and file locations

If the game folder is under `Program Files`, copying files there needs administrator rights. The log is
`cod_vr.log`; with Windows file virtualization it ends up in `%LOCALAPPDATA%\VirtualStore\...`. Setting
`LogNearEntities=1` in `[Debug]` logs the entities added near the view when you pull the trigger (used to find
effects such as muzzle flashes).

## Image quality and post-processing

The eyes are drawn into multisampled buffers (`MSAA`), resolved at the end of the frame. Anisotropic filtering is set
on every mipmapped texture when the game gives it its filter (`glTexParameterf/i` hooks). `postfx.c` runs GLSL passes
on the resolved eye images, even though the game itself is fixed-function: ambient occlusion from each eye's depth
(copied before the full-screen effect scenes clear it), contrast-adaptive sharpening, colour styles and bloom.

## Launcher and player settings

`launcher/` builds `CoD-VR-Launcher.exe` (`launcher\build_launcher.bat`; plain Win32 and GDI, the banner is a JPEG
resource decoded with OLE). It writes the player's choices to `%APPDATA%\CoD-VR\settings.ini`; the mod reads every
setting from `cod_vr.ini` and then from that file, which wins. The game's own graphics settings (texture quality,
brightness) are passed when it starts: `+set r_picmip N +set r_ignorehwgamma 1 +set r_gamma G`. The mod writes the
headset's recommended and largest eye size to `[Headset]` in the same file, so the launcher can show the resolution
of each choice.

## Building

You need Visual Studio with the C++ tools (the build uses the x86 compiler) and the Khronos OpenXR loader:

1. Download `openxr_loader_windows-<version>.zip` from
   [OpenXR-SDK-Source releases](https://github.com/KhronosGroup/OpenXR-SDK-Source/releases)
   and extract it to `deps/openxr/` (so that `deps/openxr/include` and `deps/openxr/Win32` exist).
2. Run `proxy\build.bat`. The output goes to `proxy\out\` (`opengl32.dll` and `openxr_loader.dll`).
3. `launcher\build_launcher.bat` builds the launcher; then, optionally, `installer\build_setup.bat` builds
   `installer\out\CoD-VR-Setup.exe`, which embeds those files.

Pushing a tag such as `v1.1.0` makes the GitHub Actions workflow (`.github/workflows/release.yml`) build everything
and publish a release with the setup and a zip for manual installs.

The installer uses [miniz](https://github.com/richgel999/miniz) (MIT, in `third_party/miniz`) to read the game's
`.pk3` files.

`proxy/stubs.c` and `proxy/opengl32.def` are generated by `proxy/gen_stubs.py` from the export list of the system's
32-bit `opengl32.dll` (`proxy/ogl_exports.txt`).

Tests outside the game: `proxy/test/build_test.bat` (`gltest`: proxy loading and passthrough) and
`proxy/test/build_xrtest.bat` (`xrtest`: OpenXR session, colored eyes, HUD and controller input).

## Reverse engineering tools

`tools/` has the scripts used during the investigation:

- `reacli.mjs`: a minimal MCP client that keeps one REA/Ghidra session open and runs a list of queries.
  Needs REA (`npm install -g rea-agents`), `GHIDRA_INSTALL_DIR` and `JAVA_HOME`.
- `dis.py`: disassembles code ranges with capstone.
- `scan.py`, `off2va.py`, `pe.py`, `callscan.py`: strings, offsets, imports/exports.
- `pk3scan.py`, `pk3find.py`: inspect the game's `.pk3` files (set `COD_DIR` to the game folder).

None of Ghidra's output (decompiled game code) is in the repository.
